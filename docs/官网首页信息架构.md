# TRouter 官网首页信息架构

## 1. 文档目的

本文件用于定义 TRouter 官网首页的信息架构，目标不是单纯“做一个好看的首页”，而是让首页承担以下职责：

- 让首次访问者快速理解 TRouter 是什么
- 让目标用户知道它适合谁、解决什么问题
- 让潜在付费用户知道为什么要用它
- 让访问者在 1-2 分钟内完成下一步动作

---

## 2. 首页核心目标

官网首页应服务于四类转化目标：

- 了解产品
- 查看文档
- 注册/开始使用
- 商务合作

因此首页不应该过度堆叠功能，而应该突出：

- 定位清晰
- 价值明确
- 信任增强
- 行动路径短

---

## 3. 首页建议结构

建议首页按以下顺序组织：

1. 首屏 Hero
2. 核心价值区
3. 功能能力区
4. 适用场景区
5. 模型与供应商区
6. 商业化与后台能力区
7. 使用流程区
8. 信任与差异化区
9. FAQ
10. 底部 CTA

---

## 4. 首屏 Hero

### 目标

在 5 秒内让用户知道：

- TRouter 是什么
- 为什么值得继续看
- 下一步该点什么

### 建议内容

#### 标题

TRouter：一个稳定、低门槛、可运营的多模型 AI API 网关平台

#### 副标题

兼容 OpenAI 接口，聚合多个主流模型与供应商，支持智能路由、失败回退、计费审计和后台运营，帮助开发者与团队更快构建可持续的 AI 产品能力。

#### 主按钮

- 立即开始
- 查看文档

#### 次按钮

- 查看接入示例
- 商务合作

### 右侧展示建议

- 系统结构示意图
- Dashboard 截图
- 或“统一入口 → 路由 → 多供应商”流程图

---

## 5. 核心价值区

### 目标

回答用户最关心的问题：

- 为什么不用直连？
- 为什么不是另一个普通兼容层？

### 建议四张卡片

#### 1）统一接入

一个兼容接口，接入多个模型。

#### 2）稳定路由

多供应商聚合、失败回退、健康检查。

#### 3）成本可控

根据成本、延迟和优先级做调度。

#### 4）可运营

内置 API Key、余额、账单、审计和管理后台。

## 6. 功能能力区

### 目标

### 建议按四层展示

- OpenAI-compatible API
- chat completions / models
- 流式与非流式支持

#### 调度层

- 成本优先
- 延迟优先
- 优先级回退
- 健康检查

#### 商业化层

- API Key 管理
- 余额扣费
- 交易记录
- 审计日志

#### 运营层

- 邀请码

- 后台运营能力

## 7. 适用场景区

### 目标

让不同用户快速代入自己的使用场景。

### 建议展示 4 类场景

#### AI 应用开发

快速接入多个模型，避免重复适配。

#### 多模型成本优化

通过路由选择更适合的供应商与模型。

#### 团队内部统一网关

为团队工具和内部系统提供统一模型入口。

#### 商业化平台搭建

直接拥有 API Key、计费、账单、审计和后台能力。

## 14. 页面信息密度建议

### 不建议

- 首页塞过多底层技术细节
- 首页塞完整价格表
- 首页塞大段纯文字说明

### 建议

- 首页讲清价值
- 文档页讲清接入
- 定价页讲清收费
- 后台截图建立信任

---

## 15. 首页转化路径建议

建议首页至少有两条主路径：

### 路径 A：开发者转化

首页 → 文档 → 注册 → API Key → 首次调用

### 路径 B：商务转化

首页 → 产品介绍 / 合作页 → 联系方式 → 试用 / 沟通

---

## 16. 最终建议

TRouter 官网首页最重要的，不是展示“功能很多”，而是让访问者快速形成以下认知：

- 它是一个统一 AI 接入平台
- 它不仅能接入，还能稳定路由和控制成本
- 它已经具备可运营、可收费、可管理的后台能力
- 它适合开发者、团队和商业化场景

只要这四点在首页清晰传达，转化效率就会明显高于“纯功能堆叠式首页”。
