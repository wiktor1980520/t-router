# TRouter 商务合作 FAQ 与标准话术

## 1. 文档目的

本文件用于统一 TRouter 在商务合作、渠道合作、潜在客户沟通和初步销售阶段的表达口径，避免不同场景下对项目定位、能力边界和合作方式描述不一致。

---

## 2. 使用场景

适合用于：

- 商务初次沟通
- 渠道合作介绍
- 企业客户咨询
- 社群或私聊答疑
- 官网合作页文案整理

---

## 3. 总体表达原则

### 应该强调

- TRouter 是平台能力，不只是转发层
- 统一接入 + 稳定路由 + 可运营
- 面向真实业务，而不是纯演示项目

### 不建议强调

- 不要过度承诺“支持所有模型”
- 不要过度承诺“企业级能力已经全部完善”
- 不要在未落地前承诺复杂定制

---

## 4. 一句话标准介绍

### 标准版

TRouter 是一个面向开发者与中小团队的多模型 AI API 网关平台，通过统一接口、多供应商路由、计费审计和后台运营能力，帮助团队更快构建可持续的 AI 产品能力。

### 更短版本

TRouter 是一个稳定、低门槛、可运营的多模型 AI API 网关平台。

---

## 5. FAQ：项目定位

### Q1：TRouter 是什么？

标准回答：

TRouter 是一个多模型 AI API 网关平台。它对外提供统一的 OpenAI 兼容接口，对内聚合多个模型与供应商，并通过路由、回退、计费、审计和后台配置把模型接入做成一套可运营的平台能力。

### Q2：和直接调用模型厂商 API 有什么区别？

标准回答：

直接调用通常适合单模型、单供应商和轻量场景；TRouter 更适合需要统一接入、多模型切换、稳定性控制、成本优化和后台运营的业务场景。

### Q3：和普通兼容层有什么区别？

标准回答：

普通兼容层主要解决协议适配问题，而 TRouter 更强调平台化能力，除了兼容接口，还包含路由、回退、计费、账单、审计、后台和增长工具。

---

## 6. FAQ：功能能力

### Q4：支持哪些模型？

标准回答：

TRouter 当前重点支持 OpenAI-compatible 模型，并已补充 Claude / Anthropic 和 Gemini 等 Provider 能力。整体方向是持续扩展主流模型接入能力，但会优先保证稳定性和产品闭环。

### Q5：是否兼容 OpenAI SDK？

标准回答：

是的，TRouter 的核心对外接口采用 OpenAI 兼容方式，目的是尽量降低开发者接入成本。

### Q6：是否支持流式输出？

标准回答：

支持。不同 Provider 的流式能力会根据上游能力做兼容处理，整体目标是尽量保持一致的调用体验。

### Q7：是否有后台管理能力？

标准回答：

有。TRouter 除了 API 网关外，还提供用户、API Key、模型、供应商、路由、交易、系统配置和邀请码等后台管理能力。

---

## 7. FAQ：商业化与收费

### Q8：TRouter 是怎么收费的？

标准回答：

当前最基础的模式是按量计费和余额充值，后续也规划了包月卡、套餐和企业额度包等产品形态。

### Q9：是否支持企业合作？

标准回答：

支持。TRouter 的后续规划里包括团队版、企业版、专属部署、企业额度包和更强的审计与权限能力，适合企业客户和合作方进一步沟通。

### Q10：是否支持私有化部署？

标准回答：

私有化部署属于 TRouter 的中长期合作方向之一，适合对安全、合规和独立运行有要求的客户。

---

## 8. FAQ：合作方式

### Q11：可以怎么合作？

标准回答：

目前可考虑的合作方式包括：

- 渠道推广合作
- 模型能力联合方案
- 企业客户项目合作
- 私有化或专属部署合作

### Q12：适合什么样的合作伙伴？

标准回答：

适合有 AI 应用需求、模型接入需求、行业解决方案能力或客户资源的合作伙伴。

### Q13：合作方能获得什么？

标准回答：

合作方可以利用 TRouter 的统一接入、路由和后台能力，更快落地产品和方案，降低底层重复建设成本，并把更多精力放在业务场景上。

---

## 9. FAQ：企业客户常见问题

### Q14：团队使用时如何做权限管理？

标准回答：

当前平台已有基础后台和管理能力，团队版与企业版规划中会进一步强化多成员、角色、账单和权限控制。

### Q15：如何做成本控制？

标准回答：

TRouter 的一个核心价值就是通过供应商聚合和路由策略帮助控制成本，并在后台逐步沉淀成本、收入和毛利数据。

### Q16：如何保证稳定性？

标准回答：

TRouter 通过多供应商路由、失败回退、健康检查和后续的熔断机制，来降低单点上游故障对业务的影响。

---

## 10. FAQ：路线与边界

### Q17：现在已经是企业级成熟版本了吗？

标准回答：

TRouter 当前已经具备较完整的平台雏形和商业化基础，但仍处在持续完善阶段。对外会更强调“真实可用”和“逐步走向成熟”，而不是夸大成一个已经完全成熟的重型企业系统。

### Q18：你们下一步重点做什么？

标准回答：

短期重点是支付与账务闭环、安全基线、路由稳定性和经营看板；中期再推进包月卡、团队版和企业版。

---

## 11. 标准话术模板

### 11.1 初次介绍话术

TRouter 不是单纯的模型兼容层，而是一个面向开发者和团队的 AI 网关平台。它除了统一接入多个模型，还具备路由、回退、计费、审计和后台运营能力，更适合做真实业务而不是只做 demo。

### 11.2 面向客户的话术

如果你的团队需要统一接入多个模型、控制调用成本、提高稳定性并具备后台管理能力，TRouter 会比直接调用单一模型接口更适合作为长期底座。

### 11.3 面向合作伙伴的话术

如果你们已经有业务场景或客户资源，TRouter 可以帮助你们减少底层网关、计费和后台的重复建设，把更多精力放在行业场景和客户交付上。

### 11.4 面向投资人/汇报的话术

TRouter 的价值不在于“又多支持了几个模型”，而在于它正在形成一个从模型接入、稳定路由到商业化闭环的 AI 平台基础设施。

## 12. 沟通禁区提醒

- 不要承诺尚未上线的复杂功能为“已完成”
- 不要在没有验证前承诺过于具体的 SLA
- 不要过度强调“支持所有模型”
- 不要把未来规划表述成当前现状

---

## 13. 最终建议

商务沟通里最重要的不是说得多，而是说得稳、说得一致、说得可落地。

TRouter 最适合统一表达的三个关键词是：

- 统一接入
- 稳定路由
- 可运营

只要围绕这三点展开，大部分合作沟通都能保持足够清晰和专业。
