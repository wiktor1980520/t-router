# TRouter 1.0 上线前检查清单

## 说明

本清单用于 1.0 上线前的最终核查，避免“功能看起来已经完成，但上线后出现支付、稳定性、安全性或运营问题”。

建议按照以下维度逐项确认：

- 产品功能
- 技术稳定性
- 安全与风控
- 商业化链路
- 运营准备
- 发布准备

---

## 一、产品功能检查

### 用户与账户

- [ ] 用户可以正常注册
- [ ] 邀请码注册逻辑正常
- [ ] 注册开关生效
- [ ] 登录流程正常
- [ ] 忘记密码/账号恢复策略明确
- [ ] 用户信息页可正常展示
- [ ] 手机验证码逻辑符合当前运营要求

### API Key

- [ ] 用户可以创建 API Key
- [ ] 用户可以删除 API Key
- [ ] API Key 权限限制生效
- [ ] API Key 禁用后无法调用
- [ ] API Key 展示、复制、隐藏逻辑正常

### 模型调用

- [ ] `/v1/chat/completions` 正常
- [ ] `/v1/models` 正常
- [ ] OpenAI-compatible 模型正常
- [ ] Claude 正常
- [ ] Gemini 正常
- [ ] 至少一个 Kimi/GLM 模型正常
- [ ] 流式请求可用
- [ ] 非流式请求可用

### 后台管理

- [ ] 用户管理正常
- [ ] 模型管理正常
- [ ] 供应商管理正常
- [ ] 路由管理正常
- [ ] 系统配置正常
- [ ] 邀请码管理正常
- [ ] 交易记录可查看
- [ ] 数据看板可用（总览/模型排行/邀请码渠道）
- [ ] 包月卡套餐可配置与授予
- [ ] 团队空间可创建、预算可配置、审计可导出

---

## 二、路由与稳定性检查

- [ ] 最低成本策略正常
- [ ] 最低延迟策略正常
- [ ] 路由优先级逻辑正常
- [ ] 上游失败时可自动回退
- [ ] 健康检查任务正常执行
- [ ] 延迟数据能被更新
- [ ] 失败计数能正确累积
- [ ] request_id 可在错误日志和响应中追踪
- [ ] request_id 会透传到上游请求（便于供应商侧排障）
- [ ] 所有上游 HTTP Client 设置合理超时
- [ ] 上游 4xx/5xx 错误可定位

---

## 三、账务与支付检查

### 充值流程

- [ ] 用户可以发起充值
- [ ] 支付订单可创建
- [ ] 支付回调可处理
- [ ] 支付回调幂等
- [ ] 支付回调金额与订单金额一致校验
- [ ] 支付回调原始报文可追溯（落库或可检索）
- [ ] 后台手工补单路径明确
- [ ] 交易记录与余额变化一致
- [ ] 手工充值入口仅管理员可用（禁止普通用户直充）

### 消费流程

- [ ] 成功调用后能正常扣费
- [ ] 扣费金额与 pricing 配置一致
- [ ] 审计日志与消费记录一致
- [ ] 模型 usage 为空时有兜底估算
- [ ] 流式消费与非流式消费都能正常记账
- [ ] 并发扣费下余额不会扣成负数
- [ ] 同一 request_id 不会重复扣费（幂等约束生效）
- [ ] 包月卡额度优先扣减（覆盖模型范围内）
- [ ] 包月额度不足时超额部分转按量扣费

### 财务一致性

- [ ] 余额、交易、审计三者一致
- [ ] 失败请求不会误扣费
- [ ] 上游失败后不会重复扣费
- [ ] 补单不会重复入账

---

## 四、安全与风控检查

- [ ] JWT Secret 已配置为正式值
- [ ] 不再依赖默认管理员账号密码
- [ ] API Key 存储方式符合安全要求（数据库不保存明文 Key）
- [ ] 历史明文 Key 已可逐步迁移为哈希存储（不中断存量用户使用）
- [ ] API Key 过期时间可生效（过期后拒绝请求）
- [ ] 管理员接口有鉴权保护
- [ ] 关键配置不暴露在前端
- [ ] 基础限流已启用（至少按 API Key 的 RPM 限制）
- [ ] 异常高频请求可识别
- [ ] 用户禁用后不可继续调用
- [ ] 关键后台操作有审计记录
